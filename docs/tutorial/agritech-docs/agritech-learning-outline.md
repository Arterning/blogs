# 农业科技（AgriTech）技术人学习大纲

> **定位**：面向有技术背景、零农业经验的工程师，系统建立 AgriTech 领域知识框架。
> 目标不是成为农业专家，而是能在农业数字化项目中做有效的技术决策。

---

## 一、为什么 AgriTech 值得投入

- 中国 2 亿农户，数字化渗透率不足零售业的 1/10，基础设施几乎从零建起
- 精准农业、农业保险、农产品溯源——每个方向都在重建数据层
- 门槛不高，但懂行的技术人极度稀缺，进入即有先发优势

**核心业务场景（先建感知）**

| 场景 | 核心痛点 | 技术切入点 |
|------|---------|-----------|
| 农业保险定损 | 查勘成本高、骗保难防 | 遥感影像 + 模型自动定损 |
| 智慧农业管理 | 凭经验种地，水肥药浪费严重 | IoT 传感 + 决策模型 |
| 农产品供应链追溯 | 假冒伪劣、食品安全事件频发 | 区块链 + 物联网上链 |
| 精准施药 / 植保 | 人工成本高、施药不均匀 | 无人机 + 航线规划 |

## 二、地基：农业基础知识（快速建框架）

不需要精通，但要能和农业专家对话。

### 2.1 作物生长基础

- 主要粮食作物生育期划分（水稻：播种→分蘖→拔节→抽穗→成熟）
- 关键指标：NDVI（归一化植被指数）、LAI（叶面积指数）、EVI
- 病虫害基础分类（真菌性 / 细菌性 / 虫害），对应遥感识别特征

**学习资源**
- FAO 作物生产指南（中文版）：建立作物知识体系
- 中国农业农村部官网：了解国内政策背景和补贴逻辑

### 2.2 农业气象与土壤

- 土壤质地分类（沙土 / 壤土 / 黏土）与持水能力关系
- 关键气象参数：积温（GDD）、蒸散发（ET₀）、降雨量
- 理解为什么"灌溉建议"不能只看温度，要看 ET₀ 与降雨的差值

### 2.3 中国农业政策框架

- 农村土地承包法、土地流转制度（理解数字农业为何按地块而非农户管理数据）
- 农业保险政策补贴机制（理解为何政策性农险是主要市场）
- 农产品质量安全法（追溯系统的合规依据）

## 三、核心技术栈一：遥感数据处理

### 3.1 卫星数据基础

**主要数据源**

| 卫星 | 分辨率 | 重访周期 | 免费获取 | 适用场景 |
|------|--------|---------|---------|---------|
| Sentinel-2 (ESA) | 10m | 5 天 | 是 | 作物分类、长势监测 |
| Landsat 8/9 (NASA) | 30m | 16 天 | 是 | 长期变化分析 |
| 高分系列（国产） | 2-16m | 可订购 | 部分 | 定损、精细制图 |
| 商业卫星（Planet） | 3-5m | 每日 | 付费 | 精准农业、快速响应 |

**核心概念**

- 波段组合：RGB / 近红外 / 短波红外 的用途区别
- 大气校正：DN 值 → 表观反射率 → 地表反射率
- 云遮蔽处理：SCL（场景分类图层）的使用
- 时序合成：如何用多期影像填补云的空洞

### 3.2 关键植被指数

```
NDVI = (NIR - Red) / (NIR + Red)          # 植被覆盖度，范围 -1 到 1
EVI  = 2.5 * (NIR - Red) / (NIR + 6*Red - 7.5*Blue + 1)  # 改进版，减少土壤背景影响
NDWI = (Green - NIR) / (Green + NIR)      # 水体指数，用于灌溉监测
NDRE = (RedEdge - Red) / (RedEdge + Red)  # 红边指数，对氮含量敏感
```

### 3.3 实操工具链

**数据获取**
- Copernicus Open Access Hub（Sentinel 官方下载）
- Google Earth Engine（云端处理，最推荐入门）
- USGS EarthExplorer（Landsat）

**处理工具**
- `GDAL`：栅格数据读写、投影转换的基础库
- `rasterio` + `numpy`：Python 生态核心
- `sen2cor`：Sentinel-2 大气校正官方工具
- `OTB（Orfeo Toolbox）`：大规模遥感图像处理

**学习路径**
1. Google Earth Engine JavaScript API 入门教程（官方文档）
2. 用 GEE 计算某地块一年内 NDVI 时序曲线
3. 用 Python + rasterio 本地复现同样分析
4. 实战：基于 Sentinel-2 识别某区域水稻种植面积

## 四、核心技术栈二：GIS 地理信息系统

### 4.1 基础概念

- **矢量数据**：点（采样点）/ 线（道路）/ 面（地块）及其属性表
- **栅格数据**：像元格网，每个像元有值（影像、DEM、土壤图）
- **坐标系**：WGS84（GPS 通用）vs CGCS2000（中国法定）vs 投影坐标系

> 国内项目注意：地图数据有加偏标准（GCJ-02），处理坐标时要做偏移校正。

### 4.2 农业 GIS 核心操作

- **地块管理**：多边形地块的绘制、合并、分割，属性挂载
- **空间叠加分析**：地块 × 土壤图 × 气象格网 = 精准化管理分区
- **空间插值**：克里金插值（Kriging）做土壤养分分布图
- **坡度 / 坡向分析**：DEM 派生，用于农田排水和宜机作业分析

### 4.3 工具选型

| 工具 | 定位 | 学习优先级 |
|------|------|----------|
| QGIS | 开源桌面 GIS，功能完整 | ★★★★★ 必学 |
| PostGIS | PostgreSQL 空间扩展，后端空间查询 | ★★★★ 重要 |
| Shapely + GeoPandas | Python GIS 分析 | ★★★★ 重要 |
| Leaflet / MapboxGL | 前端地图可视化 | ★★★ 按需 |
| ArcGIS / SuperMap | 商业 GIS，国内政府项目常见 | ★★ 了解 |

**学习路径**
1. QGIS 官方文档：完成基础操作教程
2. GeoPandas 入门：用 Python 做地块统计分析
3. PostGIS 实战：设计一个地块管理数据库，支持空间查询
4. 实战：用真实地块数据做农田面积统计与地图渲染

## 五、核心技术栈三：农业物联网（IoT）

### 5.1 传感器体系

**田间传感设备**

| 传感器类型 | 采集参数 | 典型精度 | 主要厂商 |
|-----------|---------|---------|---------|
| 土壤温湿度传感器 | 含水率、温度、EC 值 | ±3% | 维萨拉、METER |
| 气象站 | 温湿度、风速、辐射、降雨 | 专业级 | Davis、Campbell |
| 叶片传感器 | 叶温、叶湿、结露 | — | Decagon |
| 图像传感器 | 植株外观、病虫害图像 | — | 定制摄像头 |

### 5.2 通信协议栈

```
传感器层
  └── RS485 / SDI-12（有线短距）
  └── ZigBee / LoRa（无线低功耗，适合农田）

网关层
  └── LoRaWAN（LPWAN 主流，覆盖半径 2-15km）
  └── NB-IoT（蜂窝物联网，依赖运营商网络）

平台层
  └── MQTT（消息代理协议，标准选择）
  └── HTTP/CoAP（设备上报）
```

**重点：LoRa vs NB-IoT 选型**

| 维度 | LoRa | NB-IoT |
|------|------|--------|
| 网络依赖 | 自建网关 | 依赖运营商 |
| 覆盖 | 灵活，可按需部署 | 依赖基站分布 |
| 成本 | 自建有初期投入 | 按流量付费 |
| 适用 | 偏远农田、规模化自建 | 农田有信号覆盖 |

### 5.3 数据平台架构

```
设备层 → MQTT Broker（Mosquitto/EMQX）
         → 消息队列（Kafka）
         → 时序数据库（InfluxDB / TDengine）
         → 数据分析层（告警规则 / 模型推理）
         → 可视化（Grafana / 定制前端）
```

> TDengine 是国产时序数据库，在农业 IoT 项目中常见，超高时序写入性能。

**学习路径**
1. 搭建本地 MQTT Broker（EMQX），用 Python 模拟设备上报
2. 接入 InfluxDB，写入时序数据并用 Grafana 可视化
3. 了解 LoRaWAN 架构，搭建 ChirpStack 开源网络服务器
4. 实战：设计一套完整的田间小气候监测系统数据流

## 六、核心技术栈四：区块链农产品溯源

### 6.1 溯源系统的业务逻辑

溯源的价值不在"不可篡改"，而在**可信数据上链前的采集机制**。

核心问题：**如何保证上链数据本身是真实的？**

- 物联网采集（传感器直接上链，减少人工干预）
- 二维码 + 防伪标签（包装环节的物理防伪）
- 政府数据源对接（检测报告、检疫证明等权威数据）

### 6.2 技术选型

**联盟链（企业首选）**

| 平台 | 特点 | 适用 |
|------|------|------|
| Hyperledger Fabric | 模块化，权限可控，主流 | 供应链、政府项目 |
| FISCO BCOS | 国产开源，金链盟背书 | 国内农业项目主流 |
| 蚂蚁链 / 腾讯云区块链 | 云服务，接入简单 | 中小项目快速落地 |

> 国内农业溯源项目以 FISCO BCOS 和蚂蚁链为主，优先了解这两个。

### 6.3 核心数据结构设计

```
溯源链上存储的最小数据集：
- 产品批次 ID（链上唯一标识）
- 关键节点事件（播种、施肥、采摘、检测、出库）
- 每个事件：时间戳 + 操作主体 DID + 数据哈希
- 检测报告等大文件：存 IPFS / 对象存储，上链存哈希
```

**学习路径**
1. FISCO BCOS 官方文档：搭建本地 4 节点联盟链
2. 实现一个简单的农产品溯源合约（Solidity / WeBASE）
3. 理解 DID（去中心化身份）在溯源中的应用
4. 实战：设计一套鸡蛋从养鸡场到超市货架的完整溯源方案

## 七、综合能力：农业 AI 建模

### 7.1 产量预测模型

**特征工程关键点**
- 遥感时序特征：各生育期 NDVI 均值、积分、变化率
- 气象特征：积温、降雨、辐射的生育期累计量
- 土壤特征：有机质、pH、质地类型（分类变量）

**模型选择逻辑**
- 数据充足（>1000 地块样本）：XGBoost / LightGBM 为基线
- 数据稀缺：迁移学习，用公开数据集预训练
- 时序建模：LSTM / Transformer 对遥感时序特征建模

### 7.2 病虫害识别

- 数据获取：田间图像采集标注（ImageNet 风格）
- 模型：ResNet / EfficientNet 迁移学习为起点
- 挑战：光照不均、图像模糊、类内差异大
- 工程难点：边缘部署（无人机 / 手机端推理），模型压缩

### 7.3 灌溉决策模型

```
输入：土壤含水率、近期 ET₀、降雨预报、作物生育期
输出：今日是否灌溉 + 建议灌水量

核心方法：
- 水量平衡方程：SM(t+1) = SM(t) + 降雨 - ET₀ - 渗漏
- 基于规则：低于田间持水量的 60% 触发灌溉
- 强化学习：以产量为奖励函数，优化全季灌溉策略
```
