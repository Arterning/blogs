2.1 作物生长基础​

为什么技术人需要懂生育期​

农业数字化系统的几乎所有核心功能，背后的逻辑都是"在正确的生育期做正确的事"：

  • 遥感监测：NDVI 阈值在拔节期和苗期完全不同，用同一个模型会出错
  • 病虫害预警：稻瘟病好发于抽穗期，不同生育期的告警优先级不同
  • 灌溉决策：需水量最大的阶段是拔节到抽穗，而非全程均匀用水
  • 保险定损：冻害发生在苗期和成熟期的赔付标准不同

结论：生育期是农业系统里的"状态机"，所有业务逻辑都挂在这个状态机上。

关键遥感植被指数与生育期的关系​

植被指数不是魔法数字，它的含义需要结合生育期才能解读：

NDVI（归一化植被指数）

NDVI = (NIR - Red) / (NIR + Red)，范围 -1 到 1

植被越旺盛 → NIR 反射越强，Red 吸收越多 → NDVI 越高

解读参考（水稻，分蘖末期）：
  > 0.7：长势旺盛，建议控氮防旺长
  0.5-0.7：正常范围
  0.3-0.5：长势偏弱，检查肥水
  < 0.3：严重问题，可能病害或缺水

同样是 NDVI=0.5，在苗期是正常的，在抽穗期就是严重偏弱——这就是为什么模型要把生育期作为特征。

LAI（叶面积指数）

LAI = 单位土地面积上方，植物叶片总面积之和

LAI = 1 → 1㎡ 地面上方有 1㎡ 叶片（稀疏）
LAI = 6 → 1㎡ 地面上方有 6㎡ 叶片（水稻拔节期正常值）

用途：
- 估算光合作用潜力（LAI 越高，理论产量潜力越大）
- 指导喷药量（无人机变量施药的核心输入之一）
- 和 NDVI 有强相关性，但 NDVI 对高 LAI 段不敏感（饱和），
  此时用 EVI 或 NDRE 更准

NDRE（红边归一化植被指数）

NDRE = (RedEdge - Red) / (RedEdge + Red)

对叶片氮含量敏感（氮缺乏 → 叶绿素减少 → 红边反射变化）
用于精准施肥：叶片氮含量地图 → 变量追肥建议
需要含红边波段的卫星（Sentinel-2 Band 5/6/7，或专业无人机多光谱）

病虫害分类与遥感识别特征​

农业保险定损和病虫害预警系统都需要这个基础知识。

三大类别​

真菌性病害（最多，约占农业病害 70%）

  • 典型：稻瘟病、小麦赤霉病、玉米大斑病
  • 特征：病斑有颜色变化（黄褐色、灰白色）、蔓延速度快、潮湿环境高发
  • 遥感识别：病斑导致叶绿素降低 → NDVI 和 NDRE 下降，且空间分布往往成片

细菌性病害

  • 典型：水稻白叶枯病、玉米细菌性茎腐病
  • 特征：水渍状、腐烂、异味
  • 遥感识别：与真菌性类似，但细菌病害往往沿叶脉扩散，高分辨率影像可见纹理变化

虫害

  • 典型：稻纵卷叶螟、蝗虫、玉米螟
  • 特征：叶片缺刻（被咬食）、卷叶、排泄物
  • 遥感识别：大规模虫害导致 NDVI 快速下降；低空无人机 RGB 图像可直接识别虫孔和卷叶

技术识别难点​

问题原因工程应对
早期症状难识别发病初期 NDVI 变化 < 0.05，低于卫星噪声用无人机近距离图像 + CNN 补充卫星监测
病害与营养缺乏混淆缺氮和早期病害的 NDRE 曲线相近结合时序变化速率区分（病害变化更急剧）
标注数据稀缺田间标注成本高，难以大规模获取迁移学习 + 合成数据增强

2.2 农业气象与土壤​

土壤：农业系统的"硬件层"​

土壤质地决定了持水、保肥、通气性，进而决定了灌溉策略和施肥方案。技术系统需要知道这些，因为同样的降雨量，在沙土地和黏土地上的灌溉建议完全不同。

土壤质地分类​

土壤质地由沙粒、粉粒、黏粒的比例决定：

沙粒（>0.05mm）：颗粒大，透水快，不保水
粉粒（0.002-0.05mm）：中间
黏粒（<0.002mm）：颗粒小，保水强，透气差

国际质地三角形（简化版）：

          黏土（Clay）
          ↑ 黏粒 >40%
         /|\
        / | \
       /  |  \
壤土 ←---+---→ 粉砂壤土
（Loam）    （Silt Loam）
       \  |  /
        \ | /
         \|/
          ↓
          沙土（Sandy）
          沙粒 >70%

对农业系统设计的影响：

质地类型田间持水量凋萎系数有效水容量灌溉建议
沙土10-20%3-6%低少量多次
壤土25-35%10-14%高常规
黏土40-50%15-20%中大量少次，注意涝

田间持水量：土壤能保持的最大含水量（重力水排走后）
凋萎系数：植物无法从土壤吸水时的含水量（干旱死亡线）
有效水容量：两者之差，越大越"好用"

关键气象参数​

积温（GDD，Growing Degree Days）​

积温是驱动作物生长的"生物钟"，不是真实的时间。

日积温（GDD）= max(0, (日最高温 + 日最低温)/2 - 基础温度)

基础温度（作物开始生长的最低温度）：
  水稻：10°C
  玉米：10°C
  冬小麦：0°C

示例：某天最高温 28°C，最低温 18°C，水稻基础温度 10°C
GDD = (28 + 18) / 2 - 10 = 23 - 10 = 13

为什么积温比日期更有用？

同一品种水稻，在东北和海南，种植日期差几个月，但从播种到成熟需要的积温是固定的（约 1400-1600°C·天）。用积温而不是日期，才能做跨区域的模型迁移。

import pandas as pd

def calculate_gdd(df, base_temp=10):
    """
    df: 包含 date, tmax, tmin 列的 DataFrame
    返回带累积 GDD 的 DataFrame
    """
    df = df.copy()
    df["daily_gdd"] = ((df["tmax"] + df["tmin"]) / 2 - base_temp).clip(lower=0)
    df["cumulative_gdd"] = df["daily_gdd"].cumsum()
    return df

# 水稻生育期 GDD 阈值（参考值，品种间有差异）

蒸散发 ET₀（参考作物蒸散发）​

ET₀ 是灌溉系统最核心的输入变量，也是最容易被低估的一个。

直觉理解：ET₀ 回答的是"今天大气从土壤和植物里'抽走'了多少水"。它综合了温度、湿度、风速、辐射的影响——高温、低湿、强风、强日照会让 ET₀ 大幅上升。

灌溉需求 = 作物需水量（ETc）- 有效降雨量
         = ET₀ × 作物系数（Kc）- 有效降雨量

作物系数 Kc 随生育期变化：
  苗期：Kc ≈ 0.4（需水少）
  中期：Kc ≈ 1.2（需水最多，水稻拔节期）
  晚期：Kc ≈ 0.8（减少）

示例：某天 ET₀ = 6mm，水稻拔节期（Kc=1.2），降雨 2mm
  灌溉需求 = 6 × 1.2 - 2 = 5.2mm ≈ 52 吨/公顷

标准计算方法是 Penman-Monteith 公式（FAO 56 标准），需要温度、湿度、风速、辐射四个参数。简化版可以用温度法（Hargreaves），但误差较大。

# 用 pyet 库计算 ET₀（推荐）
# pip install pyet

import pyet
import pandas as pd

# 示例数据
weather = pd.DataFrame({
    "tmean": [25.0],   # 平均气温 °C
    "tmax":  [30.0],   # 最高气温 °C
    "tmin":  [20.0],   # 最低气温 °C
    "rhmax": [80.0],   # 最高相对湿度 %
    "rhmin": [50.0],   # 最低相对湿度 %
    "wind":  [2.0],    # 2m 高风速 m/s
    "rs":    [20.0],   # 太阳辐射 MJ/m²/day
})

# 计算 ET₀（Penman-Monteith，FAO 56）
et0 = pyet.pm_fao56(
    tmean=weather["tmean"],
    tmax=weather["tmax"],
    tmin=weather["tmin"],
    rhmax=weather["rhmax"],
    rhmin=weather["rhmin"],
    wind=weather["wind"],
    rs=weather["rs"],
    lat=39.9,          # 纬度（用于计算天文辐射）
    elevation=50,      # 海拔 m
)
print(f"今日 ET₀：{et0.iloc[0]:.2f} mm/day")

为什么"灌溉建议不能只看温度"？

高温天气 ET₀ 确实高，但如果湿度也高（比如阴雨天），ET₀ 反而可能低于晴天。同时，有效降雨量要减去地表径流，实际补充土壤的水分比降雨量小。用 ET₀ × Kc - 有效降雨 才是正确的灌溉需求计算。

2.3 中国农业政策框架​

这一节最重要。技术系统的需求往往不是来自农业逻辑，而是来自政策逻辑。不懂政策，就不理解为什么系统要这样设计——比如为什么地块管理要精确到亩、为什么农险核保要拍照上传、为什么溯源系统要有政府数据接口。

2.3.1 土地制度：理解为什么按地块管理数据​

制度背景​

中国农村土地实行"三权分置"制度：

农村土地所有权
    └── 归集体（村集体）所有
        不可买卖、不可抵押

农村土地承包权
    └── 归农户（承包主体）持有
        30年承包期（2019年起延长至2057年）
        可以继承

农村土地经营权
    └── 可流转给第三方（农业企业、合作社、家庭农场）
        可以租赁、入股、托管
        可以在金融机构抵押融资

关键点：三权分置从法律上分离了"谁拥有土地"和"谁种这块地"，为规模化经营铺平了道路——大型农业企业可以通过租赁大量农户的经营权，实现规模化种植，而不需要买地。

这对数字化系统的影响​

1. 数据单元是"地块"而非"农户"

传统思路：以农户为中心建系统
  农户A → 持有多块地 → 分散记录

现实：经营主体和承包主体分离
  承包户（农户A，拥有承包权）
      ↕ 流转合同
  经营者（农业企业B，实际耕种）
      ↕
  地块（空间实体，是唯一稳定的锚点）

系统设计：地块是中心实体，承包关系和经营关系都挂在地块上

2. 地块边界数据的法律效力

土地承包经营权证（不动产登记）已与地块坐标绑定。这意味着：

  • 地块的 GPS 坐标有法律意义，系统记录的边界必须与登记一致
  • 坐标精度要求：通常 ≤ 1m（农保、三调标准）
  • 国内法定坐标系：CGCS2000（国产测量设备默认输出）

3. 土地流转产生的系统需求

流转场景产生的数据需求技术点
农户将地块出租给合作社流转合同、起止日期、租金地块时序状态管理
合作社将多块地统一管理地块聚合、跨农户统计多边形合并、属性聚合
地块用于农业贷款抵押经营权价值评估地块质量评级（地力、收益）
政府核查流转是否合规与备案系统对接数据上报接口

关键法规​

  • 《农村土地承包法》（2019 修订）：三权分置的法律基础，承包期延长条款
  • 《农村土地经营权流转管理办法》（2022）：流转合同备案要求，流转面积超过 200 亩需登记

2.3.2 农业保险：理解政策性农险的商业逻辑​

为什么政策性农险是主要市场​

中国农业保险市场的核心特征：政府补贴驱动。

保费构成（以水稻为例）：
  保费总额：约 30-60 元/亩
      ├── 中央财政补贴：约 40%
      ├── 省级财政补贴：约 25%
      ├── 市县财政补贴：约 15%
      └── 农户自缴：约 20%（实际支出约 6-12 元/亩）

对农户来说：几乎"白送"的保险
对保险公司来说：政府是实际大客户，服务政府要求 > 服务农户需求

市场规模：中国农业保险保费 2023 年约 1,400 亿元，全球第二大农险市场（仅次于美国），且连续多年高速增长。

经办机构：主要是人保财险、中华联合、太保财险等，部分省份引入地方性农险公司。

定损流程与技术痛点​

传统定损流程：

出险报案（农户电话）
    ↓
保险公司派查勘员（驾车到农田）
    ↓
现场拍照、丈量受损面积
    ↓
填写定损单（纸质）
    ↓
理赔审核（人工复核）
    ↓
打款到农户账户

问题：
- 查勘员一天最多跑 5-8 户（农村道路差）
- 灾后几百户同时报案，根本查勘不过来
- 人工丈量误差大，容易纠纷
- 骗保手段：损失夸大、重复投保、虚假种植

数字化定损流程（遥感 + AI）：

灾害事件触发（气象预警或农户报案）
    ↓
自动拉取受灾区域卫星影像（Sentinel-2，灾前/灾后对比）
    ↓
AI 模型计算损失程度（NDVI 变化 + 作物识别）
    ↓
自动生成定损报告（损失面积、损失率、建议赔付额）
    ↓
查勘员核查异常地块（人工只介入 AI 置信度低的案件）
    ↓
理赔审核 → 打款

效果：
- 查勘效率提升 10-30 倍
- 覆盖面从"能到的地方"变成"所有投保地块"
- 骗保识别率显著提高（历史 NDVI 验证是否真实种植）

政策驱动的系统需求​

农业保险"见农险"（直达）要求（2022 年银保监政策）：

政府要求保险公司建立农户直接投保通道，减少中间层，同时要求：

1. 投保时：地块坐标采集（GPS 打点或遥感核验）
2. 承保时：与农业农村部种植业数据库比对（防虚假投保）
3. 查勘时：上传现场照片（含 GPS 水印、时间戳）
4. 理赔时：资金直接到账农户银行卡（防截留）
5. 数据上报：定期向省级农业保险监管平台推送数据

这些要求直接决定了农险系统的功能模块：地块管理 + GPS 采集 + 遥感核验 + 数据上报接口。

农险科技创业公司的定位​

理解这个生态，才能理解市场上各类农险科技公司的定位：

政府（制定规则，提供补贴）
    ↓
承保机构（人保、太保等，承担风险）
    ↓ 外包技术服务
农险科技公司
    ├── 定损服务商：遥感 + AI 定损（如水滴农业、爱科农）
    ├── 核保服务商：投保核验（防骗保）
    └── 数字农险平台：全流程系统（投保→理赔）

技术公司不承担保险风险，赚服务费或按件计价

2.3.3 农产品质量安全法：追溯系统的合规依据​

法律框架​

《农产品质量安全法》（2022 年修订） 是农产品溯源系统最直接的法律依据。

核心要求（与技术系统相关的条款）：

第十五条：农产品生产经营者应当建立生产记录制度
  → 生产记录系统：种植日期、农药化肥用量、采收日期

第二十条：鼓励建立全程追溯体系
  → 溯源系统的政策背书，各地有配套补贴

第二十三条：质量安全承诺达标合格证
  → 上市农产品必须附带合格证，部分品类要求扫码可追溯

第四十条：质量安全事故追责机制
  → 事故发生时，追溯记录作为责任认定依据

《食品安全法》 对农产品深加工环节（进入食品生产的农产品）有更严格的要求，涉及农残检测报告、供应商资质等。

可追溯数据的最小集合（合规角度）​

一条完整的追溯记录必须包含：

生产环节
  ├── 产地（地块 GPS 坐标 + 行政区划编码）
  ├── 生产主体（农户/合作社名称 + 身份证/营业执照号）
  ├── 作物品种（品种名称 + 审定编号，如国审稻 20190001）
  ├── 生产过程记录（播种、施肥、用药的品名/用量/日期）
  └── 采收信息（采收日期 + 批次号）

检测环节
  ├── 检测机构（资质编号）
  ├── 检测指标（农药残留、重金属、微生物）
  └── 检测报告（PDF + 哈希上链，防篡改）

流通环节
  ├── 出库记录（时间、目的地、运输方式）
  └── 入库记录（收货方、验收结论）

追溯码的载体与国家标准​

农产品溯源码目前没有强制统一标准，但国家推荐标准是：

国家农产品质量安全追溯管理平台（NARS）
  网址：https://www.naqs.gov.cn
  标准：GB/T 38155-2019《重要产品追溯 追溯术语》

追溯码格式：
  ├── 一维码：简单但信息量少
  ├── QR码（二维码）：主流，消费者扫码查询
  └── RFID：高价值农产品（冷链）

信息量要求：
  追溯码 → 查询系统 → 返回追溯信息页面
  （不要求把所有信息写入二维码，只需要索引号能查到就行）

地方政策差异（重要）​

追溯系统的具体要求因地而异，国家层面是鼓励性政策，各省有强制要求的品类不同：

省份强制追溯品类系统要求
山东蔬菜（出省销售必须带追溯码）与山东农产品质量追溯平台对接
广东食用农产品（规模以上主体）广东省农产品质量安全监管平台
浙江全品类试点，"浙农码"需接入浙江农业农村信息平台
国家级绿色食品、有机食品、名特优新接入国家 NARS 平台

工程建议：做追溯系统时，先明确目标省份和销售渠道，直接对接目标省级平台的接口规范，避免重复建设。

2.3.4 高标准农田：数字化基础设施的政策来源​

这是很多技术人不了解但非常重要的政策项目。

什么是高标准农田？

政府主导的农业基础设施建设项目，目标是把低产田改造成"田成方、林成网、渠相通、路相连、旱能灌、涝能排"的高产稳产田。

建设内容：
  ├── 土地平整（田块整合，适合机械化）
  ├── 灌排系统（渠道硬化、智能闸门）
  ├── 道路（机耕路，农机可进入）
  ├── 农田防护林
  └── 农田信息化（气象站、土壤传感器、视频监控）

规模：
  "十四五"目标：建成 10 亿亩高标准农田（约占耕地总面积的 50%）
  每亩建设补贴：约 1500-3000 元（中央 + 地方）
  
预算：仅中央投入已超过 1000 亿元

对农业科技公司的机会：

高标准农田建设项目往往包含"数字化"子项目：智能灌溉系统、农情监测平台、农机调度系统。这是农业 IoT 和遥感公司最主要的 B 端客户之一——甲方是县级农业农村局，资金来源是国家补贴。

典型项目立项路径：
  国家/省级财政拨款
      ↓
  县级农业农村局（建设主体）
      ↓
  公开招标（政府采购）
      ↓
  农业科技公司（系统建设+运维）

采购规模：单个县项目 300-3000 万元不等
采购频率：通常 3-5 年一轮（建设+维护）

政策框架速查表（实用总结）​

政策/制度核心内容对系统设计的影响
三权分置所有权/承包权/经营权分离地块是中心实体，而非农户
土地承包法承包期 30 年，经营权可流转系统需管理流转合同和时效
政策性农险补贴政府补贴 80%+ 保费服务政府监管需求 > 服务农户体验
农产品质量安全法生产记录 + 追溯码溯源系统的合规最小数据集
高标准农田政府基建项目，含数字化子项B 端农业 IoT 的核心采购来源
数字乡村战略（2019）国家顶层规划，推动农业数字化大量财政补贴，项目立项背书

本章小结​

农业基础知识三层结构

作物生育期（业务逻辑的状态机）
  → 所有算法和规则都要挂在生育期上，否则模型泛化性很差
  → 关键指标：NDVI / LAI / NDRE，配合生育期才有意义

气象土壤（数据来源）
  → 积温比日期更准确地描述作物发育进度
  → ET₀ 是灌溉决策的核心变量，不能只看温度
  → 土壤质地决定持水能力，影响灌溉频次策略

政策框架（商业模式的根）
  → 土地制度：地块是数字农业的基本空间单元
  → 农险补贴：政府是实际买单方，需求来自监管而非农户
  → 追溯法规：生产记录 + 溯源码是合规的最低要求
  → 高标准农田：农业 IoT 最大的 B 端采购来源
